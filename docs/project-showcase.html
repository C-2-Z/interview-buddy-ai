项目概述

不是一次性问答，而是可恢复的练习系统

用户选择岗位、难度与面试模式后，系统通过 Agent 生成或选择题目、进行多轮追问、保存证据、逐题评分，并生成综合报告。

为谁而做

求职者用于正式面试前的表达练习与弱项发现；学习者用公共题库、知识库与复练巩固知识；项目成员负责开发、测试、部署与维护。

典型场景

文字辅导面试、沉浸式语音模拟、公共题库刷题、简历辅助、知识库问答、历史报告复盘与弱项复练，覆盖从准备到复盘的全过程。

核心价值

可恢复 · 可解释 · 可复盘

以业务表为事实源，支持刷新、断线、重试与服务重启后的状态恢复；回答、评分与事件分离，便于审计与独立重建。

用户隔离

Supabase 邮箱密码认证

行级安全 RLS 与 RPC 控制数据库边界，Service 与 Repository 仍显式传递用户身份，杜绝跨用户读取。

产品模式

两条链路，两种固定策略

文字面试固定 coaching，语音面试固定 simulation。模式在创建时冻结，避免客户端任意组合造成不可测行为。

coaching 策略

允许引导、追问与结构化反馈，强调练习与理解。适合在正式面试前打磨表达与知识薄弱点。

  • 多轮追问与结构化反馈，逐题给出评分与改进建议。
  • 基于岗位 Skill 与简历上下文生成贴合的题目。
  • 回答、评分与事件分离，支持刷新与服务重启后恢复。

simulation 策略

强调连续对话、真实节奏、打断处理与异常恢复。Qwen Realtime 提供 ASR/TTS，不负责决定业务状态推进。

  • HTTP 签发短期 WebSocket token，服务端校验用户与会话。
  • 音频经 ASR 进入同一 Agent 输入流程，业务事件驱动 TTS 播放与打断。
  • 断线不丢失已确认的业务提交，支持异常恢复。

安全与隐私设计

把敏感数据挡在边界之外

所有用户输入、模型输出、上传文件与网页内容都视为不可信数据；回答、简历、Key、token 与思维链不得进入 Checkpoint、事件或日志。

身份认证

Supabase Auth + RLS

API 业务路由经 requireAuth 解析 Bearer；Service/Repository 使用中间件解析的身份，资源查询同时限制资源 ID 与所有权。SECURITY DEFINER RPC 再次校验 auth.uid() 并限制 search_path。

密钥管理

用户 API Key AES-256-GCM 加密

密钥服务端加密保存，响应脱敏，禁止客户端打包。服务角色 Key 仅限服务端，不通过 VITE_ 暴露；ENCRYPTION_KEY 与 DATABASE_URL 不写入客户端与日志。

数据最小化

正文不进事件与日志

agent_events 只保存最小化事件用于 SSE 重放，不保存回答、简历或思维链。

日志脱敏

createModuleLogger

禁止裸 console，错误元数据仅含模块、阶段、状态码、耗时与安全标识，导出前再次脱敏。

输入校验

Zod 严格 schema

HTTP 路径、查询、JSON 与表单均经类型、长度、枚举与未知字段校验，Agent 输入额外检查注入与重复操作。

答辩支持

讲解时可以顺着这条线

展开答辩速记 +
  1. 选题意义：求职者缺乏低成本的真实面试演练环境，EZMock 把表达练习、弱项发现与复盘收敛到一个系统。
  2. 架构亮点：业务表为事实源，Checkpoint 只负责恢复，agent_events 负责 SSE 重放，三者职责分离，支持断线重试与服务重启恢复。
  3. 模式设计：文字固定 coaching、语音固定 simulation，由 ADR-002 决定，避免客户端任意组合造成不可测行为。
  4. 安全边界：回答、简历、Key、token 与思维链不进 Checkpoint/事件/日志；用户 API Key 经 AES-256-GCM 加密；RLS 与 RPC 双层校验。
  5. 工程约束：新会话只写 agent-v3（ADR-001），迁移只新增不回退，外部网页只作受控证据不作指令，降低 Prompt 注入。
  6. 当前边界：尚无可运行的 Redis/BullMQ 生成 Worker，Android 商店发布与端侧推理不在当前承诺范围内，讲解时如实说明。
