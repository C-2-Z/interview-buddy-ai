# 安全与隐私设计

> 状态：当前｜维护者：项目团队｜最后核验：2026-07-16｜代码基线：`main@6958ac3`｜事实源：认证中间件、RLS/RPC、输入 schema、日志、加密与 Agent 数据最小化实现

## 1. 安全目标

- 防止未认证访问、跨用户数据访问和高权限数据库能力滥用。
- 防止 Key、token、数据库密码、简历、回答和思维链泄露。
- 将用户输入、模型输出、上传文件和网页内容都视为不可信数据。
- 在失败、重试、并发、日志和恢复链路中维持相同安全边界。

## 2. 资产与威胁

| 资产          | 主要威胁                        | 控制                                                   |
| ------------- | ------------------------------- | ------------------------------------------------------ |
| Supabase 会话 | token 窃取、过期或伪造          | Bearer 校验、HTTPS、短生命周期和服务端所有权检查       |
| 用户 API Key  | 数据库/日志/Bundle 泄露         | AES-256-GCM、服务端解密、脱敏响应、禁止客户端打包      |
| 简历和回答    | 跨用户读取、日志和 AI 状态泄露  | RLS、Repository 所有权、日志/Checkpoint/event 禁写正文 |
| Agent 状态    | Prompt 注入、非法推进、重放     | strict schema、幂等 ID、claim、版本/模式门禁           |
| 上传文件      | 恶意格式、超限、解析器攻击      | 类型/大小校验、受控解析、失败清理                      |
| 网页资料      | Prompt 注入、虚假来源、超大响应 | 来源、超时、大小、清洗、引用和降级                     |
| 语音链路      | token 重放、非法事件、资源泄露  | 短期 token、会话/模式校验、事件联合类型、关闭资源      |

## 3. 身份认证与授权

- 前端使用 Supabase Auth；API 业务路由通过 `requireAuth` 解析 Bearer token。
- Service/Repository 不信任客户端 `userId`，使用中间件解析的身份。
- 资源查询必须同时限制资源 ID 与当前用户所有权。
- 数据库启用 RLS；`SECURITY DEFINER` RPC 再次校验 `auth.uid()` 并限制 `search_path`。
- 服务角色 Key 仅限服务端，不能通过 `VITE_` 环境变量暴露。

## 4. 密钥管理

| 密钥                        | 存放与使用                                        |
| --------------------------- | ------------------------------------------------- |
| Supabase publishable key    | 可公开客户端配置，但仍依赖 RLS                    |
| Supabase service role / PAT | 仅服务端或受控运维环境                            |
| 用户模型 API Key            | 使用 `ENCRYPTION_KEY` 进行 AES-256-GCM 加密后保存 |
| Qwen/Tavily/LangSmith Key   | 仅 API 服务运行环境                               |
| `VOICE_WS_TOKEN_SECRET`     | 仅 API 服务，用于短期 WebSocket token             |
| `DATABASE_URL`              | 仅 API/测试/运维环境，不写入客户端和日志          |

密钥不得提交 Git、出现在错误响应、截图或测试夹具中。泄露后必须撤销、轮换并检查访问日志，而不是只删除本地文件。

## 5. 输入与模型安全

- HTTP 路径、查询、JSON 和表单通过 Zod/明确校验限制类型、长度、枚举和未知字段。
- Agent 输入额外检查空白、超长、复制题目、Prompt 注入和重复操作。
- Prompt 将用户、简历、知识库和网页内容标记为数据；外部文本不能改变系统规则或工具权限。
- 模型输出必须通过 JSON/schema、分数范围、文本长度和敏感字段校验。
- 不保存或展示隐藏思维链；只持久化受控决策原因、证据和用户可见解释。

## 6. 日志与可观测性安全

- 禁止裸 `console.*`，使用 `createModuleLogger(tag)`。
- `logger.error` 第一个参数传 `Error`，元数据只包含模块、阶段、状态码、耗时和安全标识。
- 不记录请求体、Authorization、Key、token、数据库 URL、简历、回答、网页全文或音频正文。
- 生产日志访问遵循最小权限和保留策略；导出日志前必须再次脱敏。

## 7. 隐私与数据治理

| 数据            | 用途               | 可见范围               | 删除入口                     |
| --------------- | ------------------ | ---------------------- | ---------------------------- |
| 账号与资料      | 认证和展示         | 用户本人、必要服务端   | 账号流程由 Supabase/运维治理 |
| 面试问答与评分  | 会话、报告和复练   | 用户本人               | 会话删除 RPC                 |
| 简历            | 面试上下文         | 用户本人、受控 AI 请求 | 简历删除接口                 |
| 知识文档与 QA   | RAG 和学习         | 用户本人               | 文档/QA/Brain 删除接口       |
| 加密 API Key    | 调用用户选择的模型 | 服务端短时解密         | 设置更新/覆盖                |
| 训练记忆        | 跨会话聚合建议     | 用户本人               | 关闭并清除记忆               |
| Agent 事件/审计 | 恢复、诊断、安全   | 用户本人或授权运维     | 按保留策略清理               |

数据收集坚持最小必要原则。第三方 AI/搜索服务只接收完成当前请求所需的最小上下文；不得把其他用户或无关历史数据拼入请求。

## 8. 保留与删除

- 用户删除业务资源后，在线主库应通过受控流程删除或解除关联。
- Agent 事件使用 `AGENT_EVENT_RETENTION_DAYS` 作为目标保留期，但清理任务上线前必须验证。
- 日志、备份和第三方服务可能按各自周期延迟物理删除；对外承诺必须与实际基础设施一致。
- 不为调试无限期保留正文或音频；测试数据必须使用脱敏/合成内容。

## 9. 安全事件响应

1. **识别**：确认影响环境、资产、用户范围和时间窗口，保存不含敏感正文的证据。
2. **遏制**：禁用受影响入口、撤销 token、轮换 Key、限制来源或临时关闭功能门。
3. **修复**：修补根因，补充测试与检测，不修改/掩盖历史记录。
4. **恢复**：分阶段恢复流量，观察认证失败、错误率、异常访问和依赖状态。
5. **通知**：按实际合规和用户影响决定通知范围；不得虚构“无数据泄露”。
6. **复盘**：记录时间线、根因、影响、行动项、负责人和完成期限。

生产环境处置、密钥轮换、数据库写操作和用户通知必须获得明确授权。

## 10. 发布安全门禁

- 认证、跨用户拒绝、RLS/RPC 和敏感字段测试通过。
- Native Bundle 不包含服务端变量。
- CORS 使用精确来源，生产只使用 HTTPS/WSS。
- 依赖、日志、错误响应和 OpenAPI 不泄露敏感信息。
- 新增状态写入覆盖幂等、并发、刷新、失败和恢复。
- 数据库迁移在隔离环境验证且有补救方案。
