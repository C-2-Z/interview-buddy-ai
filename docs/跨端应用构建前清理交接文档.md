## 1. 文档目的

本文档记录 Android 与 PC 客户端建设前的仓库清理结果、当前技术边界、验证证据和后续接入路线。后续开发者应先提交本轮清理，再单独建立跨端容器分支，避免把代码清理与 Capacitor/Tauri 平台工程混在同一个提交中。

本轮工作的原则是：只删除能够通过引用分析、类型检查、测试或生产构建证明无用的文件和逻辑，不删除现有业务能力，也不提前引入未经确认的跨端框架配置。

## 2. 当前结论

本轮共删除 49 个已跟踪文件、约 5900 行代码，并移除 29 个前端直接依赖。前端 CSS 生产产物由约 100 KB 降至 79 KB。前端 5 项测试、后端 122 项测试、前后端 TypeScript 检查及生产构建均已通过。

仓库目前仍是 Web SSR 前端与独立 Node.js API 的双服务架构，尚未创建 Capacitor Android 工程或 Tauri PC 工程。因此“代码清理”已经完成，但“原生容器接入”尚未开始。

## 3. 当前架构边界

```text
TanStack React Start 前端
  ├─ 浏览器 Supabase Auth
  ├─ HTTP / SSE 请求 Hono API
  └─ WebSocket 连接语音面试服务

Hono API 服务
  ├─ Supabase PostgreSQL / Auth
  ├─ DeepSeek / OpenAI / Anthropic
  ├─ Qwen 实时 ASR / TTS
  ├─ Interview Agent / LangGraph
  └─ 知识库、简历、题库、设置等模块
```

需要特别注意：当前 `npm run build` 生成 TanStack Start 的客户端和 SSR 服务端产物，并不是可以直接复制到 Capacitor/Tauri WebView 的纯静态 SPA 产物。原生端必须在以下方案中明确选择一种：

1. 原生壳加载已部署的 Web 地址；接入快，但依赖网络，原生体验和商店审核策略需要单独评估。
2. 新增独立的客户端构建入口，将静态前端打进原生壳，API、SSE、WebSocket 继续访问远端服务；更适合作为正式 App 路线。

建议采用第二种，并保留现有 SSR Web 版本，形成 Web 与 Native 两个构建目标，共享 `src/features` 业务模块。

### 4.5 清理未使用 API、Hook 和类型

已删除或收窄以下无调用逻辑：

- Agent 会话未使用的获取与重试包装函数。
- Brain 更新、移除文档及未使用会话更新 API。
- 非流式知识问答 API。
- 未使用的 React Query hooks、常量、类型和导出。
- 题库未使用的收藏列表请求。
- 旧版创建会话 schema 与类型。

`qa-message-bubble.tsx` 现在会真正渲染处理后的引用标记内容，修复了此前“计算了引用文本但仍渲染原始文本”的问题。

### 4.6 清理临时和一次性文件

删除：

- `__check_ps1.py`：内容实际是重复的 PowerShell 启动脚本，不是可执行 Python。
- `scripts/run_migration.sql`：已被正式 Supabase migrations 取代的一次性迁移。
- `api-server/test-alloc.ts`：临时分配测试脚本。

### 4.7 构建与质量配置调整

- 根目录与 API 的 `tsconfig.json` 已启用 `noUnusedLocals` 和 `noUnusedParameters`。
- Vite 8 使用内置 `resolve.tsconfigPaths`，移除 `vite-tsconfig-paths`。
- 删除没有安装 `concurrently` 却依赖它的失效 `dev:all` 脚本。
- 前端测试脚本改为 `npm exec --prefix api-server`，不再写死 Windows `.cmd` 路径。
- ESLint 忽略依赖、构建和运行时目录，避免扫描 `.runtime` 与生成产物。
- ESLint 与 Prettier 解耦；ESLint 检查语义问题，Prettier 单独负责格式。
- Prettier 使用 `endOfLine: auto`，避免 Windows CRLF 造成全仓误报。
- 后端日志 reporter 已补充明确类型，继续使用 `consola` 和敏感字段脱敏。
- `pdfjs-dist` 明确保留为简历解析器的直接依赖，并与现有 `pdf-parse` 依赖版本对齐。
