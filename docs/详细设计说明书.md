# 详细设计说明书

> 状态：当前｜维护者：开发与设计团队｜最后核验：2026-07-16｜代码基线：`main@6958ac3`｜事实源：前端 features、后端 modules、Agent Graph、语音与知识库实现

## 1. 模块化设计

后端功能域采用四层结构：Route 负责认证、校验、调用和错误映射；Service 编排业务流程与不变量；Repository 负责数据库/RPC 和字段映射；Schemas 定义外部输入边界。

```text
apps/api/src/modules/<feature>/
  <feature>.routes.ts
  <feature>.service.ts
  <feature>.repository.ts
  <feature>.schemas.ts
  <feature>.types.ts（按需）
```

前端功能采用独立 feature，页面路由只加载页面壳：

```text
src/features/<feature>/
  api.ts
  types.ts
  hooks/
  components/
```

## 2. Agent v3

### 2.1 冻结配置

会话创建时冻结岗位、难度、题量、模式、Skill、题库/简历/知识上下文和模型策略。后续请求不得通过客户端参数改变模式或 Agent 版本。

### 2.2 执行步骤

```text
readiness
 → create session
 → preparation / question selection
 → ask
 → input guard
 → persist answer
 → follow-up or evaluation
 → advance / report
 → emit minimal events
```

Graph 节点只保存恢复所需控制状态。答案正文、简历、网页全文、Key、token 和思维链不得写入 Checkpoint。

### 2.3 选题与追问

- 题库候选满足岗位、难度和去重条件时优先使用。
- 模型生成必须返回受 schema 约束的题目对象。
- 追问依据当前问题、用户答案和已持久化证据，禁止凭隐藏推理伪造用户事实。
- 达到追问/题量/结束条件后进入评分或报告，不允许无限循环。

### 2.4 评分与报告

- 评分输入来自已持久化问题、回答和允许的岗位上下文。
- 模型结果必须经过 JSON/schema、范围和文本长度校验。
- 最终报告聚合结构化评分、证据、优点、弱点和练习建议。
- 非法模型输出必须重试、降级或返回可恢复错误，不得写入半结构化结果。

## 3. 幂等、并发与恢复

- `inputId` 是客户端重试的幂等键。
- 服务端 claim 防止两个执行者同时推进同一会话。
- 状态推进、问题索引、评分和活动必须在业务不变量允许时写入。
- SSE 使用事件游标重放；游标失效时客户端重新读取工作区，而不是猜测状态。
- Checkpoint 缺失时允许从业务表恢复可重建状态；生产环境不得静默退化到内存 Checkpointer。

## 4. 语音设计

1. 客户端通过 HTTP 获取带过期时间的短期连接信息。
2. WebSocket 仅接受 Agent voice 会话，验证 token、用户、会话和模式。
3. 客户端二进制音频送入 Qwen ASR；最终转写进入统一 Agent 输入链路。
4. Agent 业务事件触发 Qwen TTS；音频块和阶段事件返回客户端。
5. 打断、上游超时、非法事件和断线必须释放资源，并保留已经确认的业务状态。

语音 Provider 只负责音频能力，不直接修改问题、评分或报告。

## 5. 知识库设计

- 文档入口校验类型、大小和所有权，支持文本及实现中允许的文件格式。
- Processor 解析后分块；嵌入和元数据写入用户隔离的数据表。
- Query rewriter、检索、上下文压缩和回答生成各自有长度、超时与 fallback。
- 答案必须返回可追溯来源；网页或文档内容始终作为数据而不是系统指令。
- Brain 管理文档集合；知识图谱是检索/展示增强，不替代原文来源。

## 6. Provider 与设置

用户设置决定 Provider、模型和可选 API Key。Key 只在服务端解密并短时使用；前端只获取是否配置等非敏感状态。Provider 必须统一处理超时、网络错误、限流、非法 JSON 和模型能力差异。

## 7. 前端状态与页面

| 页面/区域        | 关键状态                                        |
| ---------------- | ----------------------------------------------- |
| 首页             | 文字与语音双入口、产品能力和未登录引导          |
| 创建向导         | 配置编辑、校验、readiness、创建中、失败恢复     |
| 文字工作台       | 当前问题、输入、活动、SSE 连接、评分/完成状态   |
| 语音会话         | 设备校验、连接、聆听/识别/思考/播报、打断和重连 |
| 报告             | 总分、维度、证据、弱项和复练入口                |
| 题库/简历/知识库 | 列表、详情、空状态、错误、删除确认和权限错误    |

React Query 保存服务端状态；临时输入和设备状态留在组件/feature；页面刷新后必须从 API 重建，而不是依赖不可持久的内存对象。

## 8. UI/UX 规范

- 使用 Tailwind 设计 token、Radix 原语和共享 UI 组件，不在页面散落重复颜色和交互实现。
- 主操作、危险操作、禁用、加载、成功和失败状态必须视觉可区分。
- 弹窗提供标题、描述、焦点管理、Escape/关闭行为和破坏性确认。
- 表单错误靠近字段展示；异步错误提供重试或返回路径。
- 语音页面优先减少视觉干扰，文字页面优先保证问题、回答和反馈层级。
- 报告必须同时显示数值和文字解释，不只用颜色表达结果。
- 支持键盘操作、可见焦点、语义标签和合理对比度。
- 窄屏采用单列；Native 安全区、麦克风权限、全屏和 Wake Lock 通过平台适配层处理。

## 9. 外部集成与失败策略

| 集成             | 失败策略                                                |
| ---------------- | ------------------------------------------------------- |
| Supabase Auth/DB | 返回认证或依赖错误，不伪造成功；关键写入保持幂等        |
| 文本模型         | 超时、有限重试、schema 校验；不可用时阻塞或返回受控错误 |
| Qwen ASR/TTS     | 关闭上游和客户端连接，发送安全错误，保留已提交业务状态  |
| Tavily/公开资料  | 超时、来源/大小限制，可降级为不研究或公开 fallback      |
| 文档解析         | 拒绝不支持/损坏/超限文件，不保存未确认解析结果          |

## 10. 错误契约

服务端错误应映射为稳定 HTTP 状态和安全 `{ error, code?, details? }` 结构；客户端根据错误类别展示重试、重新认证、修改输入或联系运维。内部异常、SQL、Key 和正文不得直接返回客户端。
