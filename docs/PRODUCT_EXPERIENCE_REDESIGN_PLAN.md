# AI 面试模拟器产品体验重设计计划

> 文档目标：从求职者和成熟面试训练产品的视角，重新定义业务闭环、信息架构、关键页面和后续开发任务。
>
> 评审基线：2026-07-13，分支 `codex/agent-langgraph-foundation`，Agent Phase 1–7 已完成。

## 1. 结论先行

当前项目已经具备较强的技术底座：可恢复 Agent、多角色面试、文本与语音、岗位研究、证据评分、报告和历史记录。但从用户视角看，它仍然更像“Agent 能力演示和调试工作台”，还没有形成成熟训练产品应有的闭环。

最需要解决的不是继续堆叠 Agent 参数，而是把产品主线改成：

```text
明确训练目标 → 低门槛开始 → 沉浸式作答 → 看懂问题 → 获得具体改法 → 立即针对性复练 → 看到长期进步
```

当前主线更接近：

```text
理解技术选项 → 配置 Agent → 观察状态机 → 完成问答 → 查看分数和内部证据
```

因此建议进行一次业务逻辑和展示层的联合重设计，而不是单纯换颜色、调整卡片或增加动画。

## 2. 目标用户与核心任务

### 2.1 核心用户

1. 第一次准备面试的学生：不知道该练什么，需要默认方案和示例。
2. 有明确 JD 的求职者：希望快速发现岗位匹配差距。
3. 临近面试的用户：希望在 10–30 分钟内完成高强度模拟。
4. 需要长期训练的用户：希望根据历史弱项持续复练并看到趋势。

### 2.2 用户真正关心的问题

- 我现在应该练哪一种面试？
- 这场训练需要多久、会经历什么？
- 我是否已经准备好开始，麦克风和模型是否可用？
- 我哪里答得不好，证据是什么？
- 下一次怎样答得更具体？
- 我接下来应该练哪几题？
- 多次练习之后，我是否真的进步了？

“使用哪个模型”“当前事件游标”“Canonical Agent”“LangGraph 冻结计划”都不是普通用户的核心任务，应从主流程中隐藏。

## 3. 当前体验审计

### 3.1 P0：会阻断核心业务闭环的问题

#### A. 创建前没有可用性预检

当前用户填写完整表单并点击创建后，才可能发现 Agent 开关、数据库、模型 Key、迁移或语音服务不可用。此前出现的“New Agent interviews are currently disabled”和“Agent 服务暂时不可用”就是典型结果。

影响：用户完成了高成本输入，却只得到不可恢复的通用错误，信任迅速下降。

建议：新增统一 `readiness` 业务能力，在进入创建页时检查 Agent、checkpoint、数据库迁移、默认模型和语音能力。页面必须展示“可开始 / 需要设置 / 暂时降级”，并给出直接修复入口。

#### B. 会话生命周期不完整

后端已经暴露 `/finish`，但活动会话仍返回 `agent_finish_not_available`；前端也没有暂停、结束、放弃和稍后继续的清晰业务动作。

影响：用户开始后没有退出路径，只能关闭页面；历史记录会积累语义不明的 `active` 会话。

建议：业务状态至少区分 `preparing / in_progress / paused / completed / abandoned / failed`，实现“暂停并稍后继续”“提前结束并生成不完整报告”“放弃并归档”。删除会话时同时清理 checkpoint 和相关投影。

#### C. 本地降级能力与生产持久化边界未产品化

本地显式 MemorySaver 可以解决开发阻塞，但用户界面并不知道当前会话是否可跨重启恢复。

影响：开发或演示环境重启后，会话看似存在但 checkpoint 不可恢复。

建议：readiness 响应携带 `checkpointMode: durable | ephemeral`。非持久模式在创建前明确提示，仅用于开发；生产必须拒绝 ephemeral。

### 3.2 P1：认知门槛和信息架构问题

#### A. 技术概念泄漏过多

当前页面直接出现：

- “Agent 面试”“LangGraph”“Canonical Agent”
- “事件流在线 / 轮询恢复”
- “事件 #序号”
- “研究上下文”和原始研究状态
- 原始 `dimensionKey`
- DeepSeek / OpenAI / Anthropic 模型选择

这些信息对调试有价值，但会让普通用户误以为必须理解系统架构才能完成训练。

建议：

- 用户文案统一使用“模拟面试”“面试准备中”“连接正常”“能力反馈”。
- 技术状态收进仅开发环境可见的“诊断信息”抽屉。
- 模型默认由系统或设置决定；创建页只在“高级设置”中允许专业用户切换。

#### B. 首页入口按技术实现分组，而不是按用户目标分组

“Agent 面试”和“简历面试”不是互斥业务：简历本应是一次模拟面试的上下文来源。

建议将首页入口改为：

1. 快速模拟：只选岗位和时长，系统自动配置。
2. 针对 JD：粘贴岗位描述，自动提取能力要求。
3. 基于简历：选择简历，重点追问真实经历。
4. 弱项复练：根据最近报告自动生成训练计划。

语音/文本、单人/多角色、模型供应商属于后续配置，不应成为一级入口。

#### C. 创建表单一次暴露过多决策

岗位、角色模式、交互通道、难度、题量、模型、公司、JD、联网研究同时出现。新用户不知道不同选项会如何影响训练，也不知道题量对应时长。

建议改为两步渐进式流程：

1. 训练目标：岗位、JD/简历、期望时长。
2. 开始前确认：系统生成的面试方案、预计时长、交互方式。

“高级设置”再展开题量、角色、联网研究和模型。提供推荐默认值，例如“15 分钟快速练习”“30 分钟标准模拟”。

### 3.3 P1：面试过程不够沉浸

#### A. 面试中同时展示评分和证据

当前右侧持续展示每题评分、证据数量和研究来源。它会改变候选人的后续回答策略，也会造成明显焦虑，不符合真实面试场景。

建议默认进入“专注面试模式”：

- 主区域只保留面试官、题目、回答和进度。
- 不显示实时分数、证据和研究来源。
- 每题结束仅反馈“已记录”，整场结束后统一解释。
- 可提供独立的“教练模式”，允许逐题即时反馈，但必须在开始前明确选择。

#### B. 文本回答使用单行输入框

结构化面试回答通常需要多段 STAR 表达，单行输入和 Enter 直接提交容易误触，也不利于复查。

建议使用可自适应高度的 `Textarea`：

- `Ctrl/Cmd + Enter` 提交，Enter 换行。
- 自动保存本题草稿到本地。
- 显示“建议 1–3 分钟 / 100–500 字”，但不强制字数。
- 支持“我需要思考一下”“请重复问题”“跳过此题”等自然动作。

#### C. 准备阶段缺少可理解进度

“Agent 正在准备”不能解释为什么需要等待，也没有阶段反馈和失败恢复。

建议展示用户语言的三阶段进度：

1. 理解岗位和简历。
2. 生成本场面试方案。
3. 准备第一道题。

超过 8–10 秒时提供“继续等待”“关闭联网研究后重试”或“使用通用题库开始”。

#### D. 语音模式缺少开始前校准

用户需要在进入面试前完成麦克风权限、音量、回声、播放和网络检查，而不是进入会话后再点击“连接语音”。

建议新增语音准备页：设备选择、试听、录音回放、权限说明、网络状态和文本降级入口。面试开始后自动连接，不再暴露 WebSocket 概念。

### 3.4 P1：报告没有形成训练价值

当前报告核心是总分和一段确定性汇总，优势/弱项只是维度名称加分数。成熟训练产品应回答“哪里有问题、为什么、怎样改、下一步练什么”。

建议报告结构：

1. 结论摘要：岗位匹配度、表现等级、置信提示，而不只给一个绝对分。
2. 能力画像：维度趋势、证据充足度、面试官角色差异。
3. 逐题复盘：题目、回答、关键证据、得分理由、缺失信息。
4. 改进示范：回答结构建议和基于用户经历的提纲，避免伪造经历。
5. 行动计划：自动生成 3 个可执行练习任务。
6. 下一场推荐：一键创建弱项复练，并继承岗位、简历和难度。
7. 长期趋势：同岗位多场对比，而不是只看孤立分数。

评分必须同时展示“证据是否充分”。证据不足时，产品不应表现得像一个高置信度的精确测量工具。

### 3.5 P2：留存、信任和成熟度问题

- 历史记录缺少重命名、归档、删除、复制配置和真正的“再来一次”。
- “再来一次”当前只跳转到空白创建页，没有继承上一场配置。
- 题库与模拟面试割裂，无法从某道题直接发起专项练习。
- 设置页要求用户理解 API Key 和模型供应商，且没有连通性测试或余额/权限提示。
- 缺少首次使用引导、示例 JD、示例报告和无简历快速体验。
- 缺少隐私说明：录音是否保存、回答保存多久、如何删除和导出。
- 缺少产品指标：创建转化率、准备失败率、首题到达率、完成率、报告查看率、复练率。
- 缺少移动端和无障碍专项验收：键盘焦点、`aria-live`、44px 触控区、375px 布局、reduced motion。

## 4. 建议的新业务架构

### 4.1 一级信息架构

```text
首页
├── 今日建议 / 继续上次
├── 快速模拟
├── 针对 JD
├── 基于简历
└── 弱项复练

训练
├── 准备方案
├── 专注面试
└── 教练模式（可选）

复盘
├── 本场报告
├── 逐题复盘
├── 行动计划
└── 能力趋势

资料
├── 简历
├── 岗位/JD 档案
└── 题库

设置
├── 体验偏好
├── AI 服务状态
├── 隐私与数据
└── 高级模型设置
```

### 4.2 会话业务状态

```text
draft → validating → preparing → ready → in_progress
                                      ├── paused → in_progress
                                      ├── completed → reviewed → follow_up_created
                                      ├── abandoned
                                      └── failed → retrying
```

技术 Graph phase 仍可保留，但应由后端映射成稳定的产品状态，前端不直接解释内部节点。

### 4.3 两种训练模式

| 模式 | 用户目标 | 过程反馈 | 报告 |
|---|---|---|---|
| 模拟面试 | 尽可能接近真实面试 | 不展示即时分数 | 完成后统一复盘 |
| 教练练习 | 边答边学、快速纠错 | 每题后提供简短反馈 | 汇总改进任务 |

不要让“单面试官 / Panel”承担模式含义；它只是面试方案中的角色配置。

## 5. 后续任务计划

### Phase A：可靠开始与完整退出（P0，预计 3–5 天）

#### PX-A01 Agent readiness 模块

- 后端新增独立 `api-server/src/modules/agent-readiness/` 四层模块。
- 检查功能开关、checkpoint 模式、必要迁移、模型可用性、语音能力。
- 新增 `GET /api/agent/readiness`，只返回脱敏、用户可行动的状态。
- 前端新增 `src/features/agent-readiness/`，创建页进入时预检。

验收：任何创建失败都能在提交前被识别，或返回稳定错误码、原因和恢复动作；不再只显示“服务暂时不可用”。

#### PX-A02 会话生命周期闭环

- 定义 `paused / abandoned / failed` 等产品状态及迁移。
- 实现活动会话提前结束、暂停、恢复、放弃、删除。
- 删除流程调用 `deleteThread(sessionId)` 并清理事件、证据、研究和运行记录。
- 前端在退出面试时提供“暂停并退出 / 结束并生成当前报告 / 放弃”。

验收：用户在任何非瞬时节点都有明确退出路径；历史记录不再出现无法解释的永久 active 会话。

#### PX-A03 创建错误与恢复协议

- 将稳定后端错误码映射为中文原因、恢复 CTA 和是否保留草稿。
- 表单错误就近展示并使用 `role="alert"`。
- 创建失败后保留所有输入，支持原地重试。

验收：针对缺 Key、迁移缺失、网络失败、研究超时和模型限流分别有可操作提示。

### Phase B：重做核心创建漏斗（P1，预计 5–7 天）

#### PX-B01 目标驱动首页

- 将入口改为快速模拟、针对 JD、基于简历、弱项复练。
- “继续上次”优先于创建新会话。
- 首次用户展示 3 步价值说明和示例报告，不强制教程。

验收：新用户在不理解 Agent、模型和角色的情况下，60 秒内可到达准备页。

#### PX-B02 两步创建向导

- 第一步只收集岗位目标和上下文。
- 第二步展示系统推荐方案、预计时长和开始前检查。
- 高级选项折叠；默认模型不在主流程展示。
- 本地保存未提交草稿。

验收：主流程同时可在 375px 和桌面完成；返回上一步不丢数据；每屏只有一个主 CTA。

#### PX-B03 面试方案预览

- 将能力蓝图翻译成用户可懂的能力类别和角色安排。
- 显示预计时长、题目范围、是否使用简历/JD，不提前泄题。
- 允许调整“更偏技术 / 更偏项目 / 更偏行为”这类业务偏好。

验收：用户能在开始前回答“为什么这样安排、预计多久、将重点考什么”。

### Phase C：专注面试与语音体验（P1，预计 5–8 天）

#### PX-C01 专注面试工作台

- 默认隐藏研究、事件号、技术状态和即时分数。
- 单独提供仅开发环境出现的诊断抽屉。
- 用产品状态展示进度和等待反馈。
- 支持暂停、提前结束和安全离开确认。

验收：主屏首要视觉只有当前问题、对话和回答动作；技术名词不出现在正式用户路径。

#### PX-C02 文本作答体验

- 使用多行输入、草稿自动保存、`Ctrl/Cmd + Enter` 提交。
- 增加重复问题、思考、跳过等显式动作。
- 提交期间锁定重复操作并给出清晰进度。

验收：页面刷新后未提交草稿仍可恢复；键盘和屏幕阅读器可完成整场面试。

#### PX-C03 语音准备与降级

- 创建前完成麦克风、播放、权限、网络测试。
- 进入会话后自动连接。
- ASR/TTS 失败时一键切换文本，保留会话和当前题。
- 明示录音是否存储及保留策略。

验收：权限拒绝、设备缺失、网络断开和语音供应商失败均有文本恢复路径。

### Phase D：报告与复练闭环（P1，预计 7–10 天）

#### PX-D01 扩展报告业务模型

- 报告投影增加逐题反馈、维度理由、证据充分度和改进任务。
- 区分未完成报告和完整报告，避免错误比较。
- 为趋势比较定义稳定的标准维度映射。

验收：每个结论可追溯到候选人回答证据；证据不足必须显式标识。

#### PX-D02 报告页重设计

- 报告从工作台侧栏独立为完整页面。
- 首屏给出结论和三项优先行动，不先堆图表。
- 支持逐题展开、复制复盘笔记、导出 PDF/打印。
- 图表提供文本摘要和数据表替代。

验收：用户查看报告后能明确说出“保留什么、改什么、下一步练什么”。

#### PX-D03 弱项复练

- 从报告一键创建复练计划，继承岗位、简历、难度和弱项维度。
- 题库详情可直接发起单题教练练习。
- 历史页增加同岗位趋势和复练关系。

验收：完成报告到开始下一次针对性练习不超过两次点击。

### Phase E：账户、信任和增长基础（P2，预计 5–8 天）

#### PX-E01 设置与模型能力重构

- 默认隐藏模型技术细节，展示“AI 服务可用 / 需要设置”。
- 提供 Key 连通性测试、错误解释和官方获取入口。
- 高级用户才选择供应商和模型；显示实际生效模型。

#### PX-E02 历史和数据管理

- 支持重命名、归档、删除、复制配置、导出。
- 建立隐私与保留策略页面。
- 删除动作可审计并有确认，必要时提供短时撤销。

#### PX-E03 产品指标与实验

- 埋点：创建页到达、readiness 失败、创建成功、首题到达、完成、报告查看、复练创建。
- 指标按文本/语音、首次/复访、入口来源拆分。
- 所有事件禁止包含回答正文、API Key 或简历原文。

### Phase F：质量门禁（贯穿所有 Phase）

- 375 / 768 / 1024 / 1440px 响应式验证。
- 键盘完成关键流程，焦点顺序正确。
- 触控目标至少 44×44px。
- 正文对比度至少 4.5:1，颜色不是唯一状态载体。
- 动态状态使用 `aria-live`，错误使用 `role="alert"`。
- 支持 `prefers-reduced-motion`。
- 前端路由级代码拆分，避免当前大于 500kB 的入口包继续增长。

## 6. 推荐实施顺序

严格按以下顺序推进：

1. `PX-A01` readiness。
2. `PX-A03` 错误恢复。
3. `PX-A02` 生命周期。
4. `PX-B01` 和 `PX-B02` 创建漏斗。
5. `PX-C01` 专注工作台。
6. `PX-C02` 文本输入。
7. `PX-D01` 报告数据模型。
8. `PX-D02` 报告页。
9. `PX-D03` 弱项复练。
10. 语音校准、设置、历史和指标。

不要先做视觉换肤。readiness、生命周期和报告数据模型没有完成前，大规模调整视觉会产生返工。

## 7. 成功指标

建议用以下指标判断重设计是否有效：

| 指标 | 建议目标 |
|---|---:|
| 创建页到首题到达率 | ≥ 85% |
| 创建失败中可自助恢复比例 | ≥ 90% |
| 标准模拟完成率 | ≥ 65% |
| 报告查看率 | ≥ 80% |
| 报告到弱项复练转化率 | ≥ 25% |
| 首次用户开始训练中位时间 | ≤ 60 秒 |
| 语音失败后文本降级成功率 | ≥ 95% |
| 关键流程键盘可完成率 | 100% |

指标是产品假设，不应在没有基线数据时被当成已经实现的结果。

## 8. 明确不建议做的事

- 不要把更多 LangGraph 节点、事件或模型参数直接展示给普通用户。
- 不要把“Agent 自主程度”作为主卖点；用户购买的是训练结果和确定性体验。
- 不要在面试过程中默认展示实时分数。
- 不要用一个综合分替代证据、置信度和具体改进建议。
- 不要在 readiness 和生命周期未完成前继续增加新的面试类型。
- 不要让 MemorySaver 进入生产环境。
- 不要为了“像 AI 产品”堆积渐变、发光和无意义动画；反馈速度和状态清晰度优先。
