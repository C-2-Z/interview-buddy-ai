# 忘记密码功能设计

## 目标

为现有邮箱密码认证补充完整的密码恢复闭环：用户从登录页申请重置邮件，在 Web 或 Tauri 桌面端打开邮件链接，设置新密码后返回登录页。流程不得泄露邮箱是否已注册，并应复用现有 Supabase Auth 与跨端运行时配置。

## 范围

- 登录态页面增加“忘记密码？”入口。
- 提供重置邮件申请表单与发送成功状态。
- 提供恢复链接落地页、新密码确认表单与完成状态。
- Web 使用 HTTPS 页面回跳；Tauri 使用 `interviewbuddy://` 深链回到应用。
- 补齐 Tauri 当前预留的深链监听能力，并让恢复链接可交换为 Supabase 会话。
- 不增加短信恢复、管理员重置、验证码输入或自定义邮件服务。

## 架构与模块边界

新增独立前端功能目录 `src/features/password-recovery/`，避免继续扩大认证路由：

- `api.ts`：封装 `resetPasswordForEmail`、恢复会话建立与 `updateUser`。
- `types.ts`：定义恢复步骤、提交结果和可展示错误类型。
- `constants.ts`：集中维护密码长度和用户文案。
- `hooks/use-password-recovery.ts`：管理发送邮件、确认恢复会话、更新密码及加载状态。
- `components/forgot-password-form.tsx`：收集邮箱并显示统一成功提示。
- `components/reset-password-form.tsx`：收集并校验两次新密码。
- `components/password-recovery-page.tsx`：根据恢复阶段组合表单和结果视图。

现有登录页面业务组件迁入独立认证 feature，`src/routes/auth.tsx` 仅保留路由声明与页面壳。新增 `src/routes/auth.reset-password.tsx` 作为薄路由入口。Tauri 深链逻辑仍归属现有 `tauri-deep-link` feature，只增加真实监听、URL 解析和将恢复回调交给密码恢复模块的连接点。

## 用户流程

### 申请重置

1. 用户在登录表单点击“忘记密码？”。
2. 页面切换到邮箱输入表单，默认保留登录表单中已输入的邮箱。
3. 提交后调用 Supabase `resetPasswordForEmail`，并传入当前平台的恢复回跳地址。
4. 无论邮箱是否存在，都显示“如果该邮箱已注册，你将收到重置邮件”的中性提示。
5. 用户可返回登录页或重新发送；提交期间禁止重复请求。

### Web 恢复

1. 邮件链接落到 `/auth/reset-password`。
2. Supabase 客户端从回调参数恢复认证会话，并等待恢复事件或当前有效用户。
3. 会话有效时显示新密码表单；链接无效、过期或缺少恢复会话时显示错误及“重新发送邮件”入口。
4. 两次密码一致且满足最小长度后调用 `updateUser({ password })`。
5. 更新成功后退出临时恢复会话并引导用户返回登录。

### Tauri 恢复

1. Native 构建生成 `interviewbuddy://auth/reset-password` 回跳地址。
2. 系统通过 Tauri deep-link 插件唤起应用；应用同时处理冷启动 URL 与运行中 URL。
3. 对 PKCE 回调提取授权码并调用 `exchangeCodeForSession`。
4. 会话交换成功后导航到重置密码页面，后续流程与 Web 共用同一 Hook 和表单。
5. 非预期协议、主机、路径或缺少授权码的 URL 被拒绝，且不写入日志敏感参数。

## 回跳配置

运行时配置扩展为区分普通认证回跳和密码恢复回跳。Web 默认基于当前 origin 生成 `/auth/reset-password`；Native 默认使用注册的 `interviewbuddy://auth/reset-password`。显式环境变量可覆盖默认值，以适配不同部署域名。

Supabase 控制台必须将 Web 恢复 URL 和 Tauri 自定义协议加入允许的 Redirect URLs。若 Supabase 托管策略不接受自定义协议，则使用受信任 HTTPS 中转页立即跳转到应用协议；中转页只转发 Supabase 返回的授权参数，不保存或记录它们。

## 校验与错误处理

- 邮箱使用浏览器 email 校验并在提交前去除首尾空白。
- 新密码与现有注册规则一致，最少 6 个字符；确认密码必须完全一致。
- 发送邮件成功提示不区分已注册与未注册邮箱，降低账号枚举风险。
- 用户可操作错误使用中文稳定文案；底层 Supabase 错误不直接作为最终界面文案。
- 过期链接、重复使用链接、网络失败和会话交换失败均提供明确重试路径。
- 不记录邮箱、恢复 token、授权码或新密码。

## 测试策略

按测试驱动顺序实现：

1. 纯函数测试覆盖 Web/Native 恢复回跳地址生成和非法地址拒绝。
2. API 层测试覆盖发送邮件参数、统一结果、更新密码与临时会话退出。
3. 状态逻辑测试覆盖发送中、发送成功、链接无效、会话有效和更新成功。
4. 表单测试覆盖邮箱预填、密码长度、两次密码不一致及重复提交保护。
5. 深链解析测试覆盖冷启动、运行中回调、错误协议、错误路径和缺少 code。
6. 执行前端定向测试、完整测试、Lint、Web 构建与 Native 构建验证。

## 验收标准

- 登录页可进入忘记密码流程并返回。
- 已注册用户可在 Web 与 Tauri 中通过邮件链接设置新密码。
- 未注册邮箱收到与已注册邮箱相同的页面反馈。
- 无效或过期链接不会展示密码提交表单。
- 密码更新成功后旧密码失效，新密码可正常登录。
- 路由保持薄入口，新业务位于独立 feature，新增函数、类型和文件满足项目注释规范。
