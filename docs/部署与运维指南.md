# 部署与运维指南

> 状态：当前｜维护者：开发与运维团队｜最后核验：2026-07-16｜代码基线：`main@6958ac3`｜事实源：构建脚本、Vercel/Tauri 配置、API 启动入口和环境变量样例

## 1. 部署组成

| 组件       | 产物/运行方式                                                             | 关键依赖                                |
| ---------- | ------------------------------------------------------------------------- | --------------------------------------- |
| Web SSR    | `npm run build` → `apps/web/dist/client`、`apps/web/dist/server`          | Node SSR、公开 Supabase/API 配置        |
| API        | `npm run build:api` → `apps/api/dist`                                     | Node、Supabase、数据库、模型/语音密钥   |
| Native SPA | `npm run build:native:dev`/`build:native` → `apps/web/dist-native/client` | 绝对 HTTPS API URL                      |
| Windows    | Tauri 2 打包                                                              | Rust、WebView2、Native SPA              |
| 数据       | Supabase PostgreSQL/Auth                                                  | migrations、RLS、RPC、Checkpoint schema |

## 2. 环境与密钥边界

- 客户端允许：`VITE_SUPABASE_URL`、`VITE_SUPABASE_PUBLISHABLE_KEY`、`VITE_API_URL`、可公开回调地址。
- 服务端专用：service role、PAT、`DATABASE_URL`、模型/语音/搜索 Key、`ENCRYPTION_KEY`、`VOICE_WS_TOKEN_SECRET`、LangSmith Key。
- Native 生产 API 必须为绝对 HTTPS；语音通过 WSS。
- CORS 只接受内置 Web 来源和 `CORS_ALLOWED_ORIGINS` 中的精确来源；拒绝通配符。

## 4. 数据库发布

1. 比较目标环境已应用 migration 与仓库历史。
2. 在隔离数据库验证待发布增量、RLS、RPC、索引和补救 SQL。
3. 备份或确认平台恢复点，获得明确授权。
4. 只执行已审查的新增 migration。
5. 验证 `check_agent_readiness()`、关键表/RPC 和跨用户拒绝。

当前 migration history 未治理，禁止全量 `supabase db push`、`db reset`、`migration repair` 和回写历史文件。

## 5. API 发布

```powershell
npm ci
npm run build:api
npm run start -w @ezmock/api
```

API 必须使用可持久 Node 进程并支持 HTTP upgrade。生产环境需要 Postgres Checkpoint；不得启用内存 Checkpointer。发布后验证 `/api/health`、`/api/agent/readiness`、认证业务接口和 `/api/voice/ws` upgrade。

## 6. Web 与 Native 发布

Web 发布 `npm run build` 产物，并保证 API 代理/地址与 CORS 匹配。Native 发布前设置生产 `VITE_API_URL`，执行 `build:native`、`verify:native` 和目标设备测试，再运行 Tauri 打包脚本。桌面容器不包含 API 服务、数据库或任何服务端密钥。

Android 当前只有技术基础和规划，未完成目标设备、签名、权限和应用商店验收，不得宣称已正式发布。

## 7. 可观测性

至少观测：

- API 存活、错误率、P50/P95 延迟和进程资源。
- readiness 阻塞原因、Agent 创建/输入/完成/失败数量和重试率。
- 模型、Tavily、Qwen ASR/TTS 的超时、限流和失败率。
- SSE 连接/重放失败、WebSocket 连接/异常关闭和并发会话。
- 数据库连接、RPC 错误、Checkpoint 失败、迁移状态和存储增长。

日志必须使用安全元数据。当前若没有统一指标后端，应通过受控平台日志与健康检查人工核验，并在路线图跟踪自动化缺口。

### 7.1 题目多样性只读统计

以下查询只读业务审计字段，不读取回答、简历或 Prompt。`:from` 由运维平台绑定时间参数，禁止把查询改成写操作。

```sql
-- 首题 bank/model 占比
SELECT COALESCE(selection_tier, CASE source WHEN 'bank' THEN 'bank_legacy' ELSE 'model_legacy' END) AS tier,
       count(*) AS questions,
       round(100.0 * count(*) / sum(count(*)) OVER (), 2) AS percentage
FROM public.interview_questions
WHERE order_index = 0 AND created_at >= :from
GROUP BY 1 ORDER BY 2 DESC;

-- 同用户 90 天首题题族重复率
WITH first_questions AS (
  SELECT s.user_id, q.session_id, q.question_family_key, q.created_at
  FROM public.interview_questions q
  JOIN public.interview_sessions s ON s.id = q.session_id
  WHERE q.order_index = 0
    AND q.question_family_key IS NOT NULL
    AND q.created_at >= now() - interval '90 days'
)
SELECT round(100.0 * avg((EXISTS (
  SELECT 1 FROM first_questions previous
  WHERE previous.user_id = current.user_id
    AND previous.question_family_key = current.question_family_key
    AND previous.created_at < current.created_at
))::int), 2) AS repeated_first_question_family_percentage
FROM first_questions current;

-- baseline 比例与 Planner repair 率
SELECT strategy_source, count(*) AS revisions,
       round(100.0 * count(*) / sum(count(*)) OVER (), 2) AS percentage,
       round(100.0 * avg((repair_count > 0)::int), 2) AS repair_percentage
FROM public.agent_strategy_revisions
WHERE created_at >= :from AND strategy_source IS NOT NULL
GROUP BY strategy_source;

-- 补题、追问决策和评分稳定错误码
SELECT error_code, count(*) AS failures
FROM public.agent_operations
WHERE status = 'failed' AND updated_at >= :from
  AND error_code IN ('agent_question_unavailable','agent_decision_unavailable','agent_scoring_unavailable')
GROUP BY error_code ORDER BY failures DESC;

-- 工具 skipped/failed 比例
SELECT tool_name, status, count(*) AS runs,
       round(100.0 * count(*) / sum(count(*)) OVER (PARTITION BY tool_name), 2) AS percentage
FROM public.agent_tool_runs
WHERE created_at >= :from AND status IN ('completed','skipped','failed')
GROUP BY tool_name, status ORDER BY tool_name, status;

-- 按岗位族、难度、角色和维度检查可用题族覆盖
SELECT family.job_family_key, q.difficulty, q.role_type, q.dimension_key,
       count(*) AS questions,
       count(DISTINCT q.question_family_key) AS question_families
FROM public.question_bank q
CROSS JOIN LATERAL unnest(q.job_family_keys) AS family(job_family_key)
WHERE q.active
GROUP BY 1,2,3,4
ORDER BY 1,2,3,4;
```

内置岗位矩阵发布验收要求首题模型补题率为 0；同用户相同配置连续 5 场至少覆盖 3 个首题题族；候选充足时单场 10 题不得重复题族。Wikimedia-only readiness 应单独统计为 degraded，不能并入 Tavily/Qwen 完整可用数。

## 8. 运维目标

以下是发布验收目标，不代表已有自动 SLO 平台：

| 指标           | 目标/处理                                               |
| -------------- | ------------------------------------------------------- |
| API 健康       | 连续失败立即阻止发布或触发回滚                          |
| 核心请求成功率 | 发布窗口内不得显著低于发布前基线                        |
| Agent 交互超时 | 受 `AI_INTERACTIVE_TIMEOUT_MS` 控制，超时返回可重试错误 |
| 数据一致性     | 不允许重复回答、重复推进、跨用户访问或报告与状态分叉    |
| 敏感数据       | 日志、事件、Checkpoint 和 Bundle 中发现即按安全事件处理 |

量化告警阈值应在获得真实多样本基线后确定，不使用单次最快值。

## 9. Runbook

### 9.1 API 无法启动

检查 Node 版本、依赖、根 `.env`、端口、Supabase/数据库连通性和构建产物。不要通过打印完整环境变量排错。

### 9.2 readiness 阻塞

按响应中的依赖项检查 Agent 功能门、模型配置、数据库 RPC/Checkpoint schema 和语音端点。不得绕过 readiness 创建会话。

### 9.3 Agent 卡住或重复推进

只读检查会话、operation、activity、event、业务问题/消息和 Checkpoint 状态；确认 `inputId` 与 claim。未经授权不手工改生产状态。

### 9.4 SSE/语音故障

验证反向代理流式传输和 upgrade、HTTPS/WSS、token 时钟、CORS、上游 Qwen 和客户端重连。关闭遗留连接，保留已经确认的业务状态。

### 9.5 数据库或迁移异常

停止继续发布，保存错误和目标环境 migration 列表，使用已审查补救方案。禁止 reset 或 repair 掩盖漂移。

### 9.6 密钥疑似泄露

立即限制入口并轮换对应凭据，检查 Git、日志、Bundle 和第三方访问记录，评估用户影响并按[安全事件响应](安全与隐私设计.md)处理。

## 10. 回滚

- 应用回滚到上一已验证版本，并保持数据库向前兼容。
- 数据库优先使用新的补救 migration，不删除已应用 migration。
- 若新客户端依赖不可逆 schema，必须先设计兼容窗口再发布。
- 回滚后重新执行健康、认证、readiness、核心 Agent、SSE/语音和数据一致性检查。
