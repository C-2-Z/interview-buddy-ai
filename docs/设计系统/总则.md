# EZMock 设计系统

> 状态：当前｜维护者：UI/UX 团队｜最后核验：2026-07-16｜事实源：`src/styles.css`、`src/components/ui/` 与各组件实现

## 1. 产品特征

EZMock 是面向求职者的职业训练 SaaS 产品。界面必须给人沉稳、可信、内容优先、高效的感觉，避免儿童教育产品或装饰性 AI Demo 的观感。

## 2. 基础规范

### 2.1 主题与调色板

- 默认浅色职业工作区；语音面试时使用深色沉浸模式。
- 主色：招聘蓝 `#0369A1`；配合天空蓝 `#0EA5E9`；成功绿 `#16A34A`；中性表面使用 Slate 系列。
- 所有颜色通过语义化 OKLCH Token 定义在 `src/styles.css` 中，组件不得引入原始品牌色。
- 字体栈：`Noto Sans SC`, `Microsoft YaHei UI`, `PingFang SC`, `system-ui`, `sans-serif`。不拉取远程字体。
- 字号阶梯：12 / 14 / 16 / 18 / 24 / 32。移动端正文至少 16px。
- 间距以 4px 为基数，8px 节奏。页面区域使用 24–48px 分隔。
- 圆角：控件 12px，卡片 16px，功能面板 20px。阴影克制，仅用于层级表达。

### 2.2 交互规则

- 每页只有一个主要操作。危险操作与被保护区域物理分离并需确认。
- 触摸目标至少 44×44px，间距至少 8px。
- 动效时长：快速 180ms，标准 240ms，面板 300ms。仅使用透明度和变形。
- 始终提供可见键盘焦点。尊重 `prefers-reduced-motion`。
- 加载、空态、成功、警告和错误状态必须同时包含文字和图标；颜色不能作为唯一信号。

### 2.3 响应式与无障碍

- 需要核验的断点：375、390、768、1024、1440px，以及移动端横屏。
- 桌面使用可折叠侧边栏，移动使用带标签的 Sheet 导航。
- 普通文本对比度满足 WCAG AA 4.5:1，大文本和非文本 UI 满足 3:1。
- 保留浏览器返回、路由深链、滚动状态和表单草稿。

### 2.4 反模式

- 禁止使用表情符号作为导航或结构图标。
- 禁止在会话中切换文字/语音模式。
- 语音房间不展示完整题目列表或回答编辑器。
- 不展示自创分数、图表、简历指标或参考答案。
- 不使用装饰性毛玻璃效果、过度渐变、长动画或仅悬停操作。

## 3. 页面专项覆盖

### 3.1 文本面试工作台

- 为扫描和持续书写优化，而非沉浸。
- 保留可见进度、当前题目、对话历史和稳定的回答输入区。
- 窄屏收起二级题目导航。
- 不引入麦克风、播放、WebSocket 或语音阶段控件。

### 3.2 面试报告页

- 以总分和 AI 摘要开头，后展示每题证据。
- 仅使用已有数据：总分、每题分数、回答和反馈。
- 卡片避免打印分页；导航和操作在打印时隐藏。
- 缺失或部分分数显示显式中性状态，不使用零填充图表。

### 3.3 语音面试会话页

- 在深色低干扰表面使用语义化 `voice-*` 色板。
- 导航可触及但视觉低调；会话状态、对话和控制按钮拥有主导层次。
- 必需状态：断开、连接中、说话中、倾听中、思考中、已评分、已打断和错误。
- 录音时只有一个主要操作：结束回答。AI 播放时以打断为上下文操作。
- 移动控制坞保留 safe-area 内边距，不遮挡会话内容。
- 诊断信息默认收起。面向用户的恢复指引出现在技术细节之前。
