# 数据模型设计

> 状态：当前｜维护者：后端与数据库团队｜最后核验：2026-07-16｜代码基线：`main@6958ac3`｜事实源：`supabase/migrations/`、Repository、RPC 调用与 LangGraph Checkpoint 配置

## 1. 数据原则

- `auth.users` 是身份根；用户资源通过 `user_id` 或可追溯会话关系归属用户。
- 业务表是面试事实源；Checkpoint 只保存 Graph 恢复状态；事件表只保存重放事件。
- 浏览器使用用户 token 和 RLS；服务端高权限访问仍必须显式校验用户所有权。
- 迁移只能追加唯一时间戳文件，不修改历史 migration。
- 数据库字段使用 snake_case，API/前端映射为 camelCase。

## 2. 关系概览

```text
auth.users
 ├─ profiles
 ├─ user_settings
 ├─ resumes
 ├─ favorite_questions → question_bank
 ├─ interview_sessions
 │   ├─ interview_questions
 │   ├─ interview_messages
 │   ├─ answer_evidence
 │   ├─ question_evaluations
 │   ├─ agent_events / operations / runs / activities
 │   ├─ agent_strategy_revisions / tool_runs / citations / research_sources
 │   └─ langgraph checkpoints（按 thread_id 关联，不作为业务外键事实）
 ├─ agent_training_profiles
 └─ knowledge_documents → chunks → graph_edges
     ├─ knowledge_brains ↔ knowledge_brain_documents
     └─ qa_sessions → qa_messages
```

## 3. 用户与配置

| 表                        | 职责                                | 关键安全边界                             |
| ------------------------- | ----------------------------------- | ---------------------------------------- |
| `profiles`                | 用户展示资料                        | `id = auth.uid()`                        |
| `user_settings`           | Provider、模型、加密 Key 等用户配置 | 仅本人；Key 不明文返回                   |
| `resumes`                 | 简历元数据与解析内容                | 仅本人；正文不得进入日志/事件/Checkpoint |
| `agent_training_profiles` | 聚合训练记忆和授权                  | 只保存维度聚合，不保存回答全文           |

## 4. 面试核心

| 表                     | 职责                                                 |
| ---------------------- | ---------------------------------------------------- |
| `interview_sessions`   | 会话身份、用户、状态、模式、版本、冻结配置、报告摘要 |
| `interview_questions`  | 题目、顺序、来源、题族、选择审计、状态与会话关系     |
| `interview_messages`   | 用户和面试官可审计消息                               |
| `answer_evidence`      | 从回答提取的评分证据                                 |
| `question_evaluations` | 单题结构化评分与反馈                                 |

会话写入必须保持版本、模式、当前问题、问题索引、完成状态和报告之间的一致性。Agent v1/v2 数据只用于历史兼容读取。

## 5. Agent 控制与审计

| 表                          | 职责                              | 内容限制                             |
| --------------------------- | --------------------------------- | ------------------------------------ |
| `agent_events`              | SSE 持久事件与游标                | 最小化 payload，不含回答/凭据/思维链 |
| `agent_operations`          | 幂等操作和 claim/commit/fail 状态 | 操作标识、状态、安全摘要             |
| `agent_runs`                | 执行审计与安全指标                | 不保存模型隐藏推理                   |
| `agent_activities`          | 用户可见阶段进度                  | 受控标题、描述、进度和状态           |
| `agent_strategy_revisions`  | Agent v3 策略修订                 | 结构化计划，不含敏感正文             |
| `agent_tool_runs`           | 工具调用审计                      | 工具名、状态、耗时和安全摘要         |
| `agent_knowledge_citations` | 研究/知识引用                     | 来源、片段标识和最小元数据           |
| `agent_research_sources`    | 受控网页研究来源                  | URL、来源、摘要和校验状态            |

`background_jobs` 来自旧渐进生成迁移，但当前没有可运行的 Redis/BullMQ generation Worker，不得据此假设后台生成可用。

`interview_questions` 的新增可空审计字段为 `question_family_key`、`selection_tier`、`selection_score` 和 `selection_reason_code`；历史行允许为空。`agent_strategy_revisions.strategy_source` 仅允许 `model_enhanced`/`baseline`，`repair_count` 记录最多一次结构修复。

## 6. 题库与知识库

| 表                            | 职责                           |
| ----------------------------- | ------------------------------ |
| `question_bank`               | 公共题目和分类元数据           |
| `favorite_questions`          | 用户收藏关系                   |
| `knowledge_documents`         | 用户知识文档及处理状态         |
| `knowledge_chunks`            | 文档分块、文本和向量相关元数据 |
| `knowledge_graph_edges`       | 用户图谱边                     |
| `knowledge_brains`            | 用户知识集合                   |
| `knowledge_brain_documents`   | Brain 与文档多对多关系         |
| `qa_sessions` / `qa_messages` | 知识问答会话和消息             |

所有知识表必须保持用户隔离；QA 引用必须能回到用户有权访问的文档/分块。

`question_bank` 使用 `job_family_keys`、`intent_key`、`stage_keys`、`question_family_key`、`quality_score` 和 `active` 作为统一分类与下线契约。角色、准确难度和主维度是硬约束；岗位、阶段、意图、主题、证据目标和质量用于固定权重排序。当前会话排除相同题目、规范文本和题族，用户近 90 天历史用于题族轮换。

## 7. LangGraph Checkpoint

`langgraph` schema 包含 `checkpoint_migrations`、`checkpoints`、`checkpoint_blobs` 和 `checkpoint_writes`。生产环境使用 PostgresSaver；仅本地显式允许时可使用内存 Checkpointer。

允许保存：会话/用户标识、阶段、角色计划、索引、幂等标识、证据 ID、受限冻结配置和控制决策。

禁止保存：回答、简历、网页全文、API Key、token、数据库凭据、Authorization 和思维链。

## 8. 关键 RPC

| 类别       | 当前职责                                         |
| ---------- | ------------------------------------------------ |
| readiness  | `check_agent_readiness` 验证数据库能力和运行门禁 |
| 创建与幂等 | 创建会话、claim/commit/fail Agent operation      |
| 输入与推进 | 接受输入、提交追问/下一题、更新问题投影          |
| 评分报告   | 提交单题评分、标记失败、最终化报告               |
| Agent v3   | 提交策略、准备、问题、评分、失败 operation 和工作区投影 |
| 生命周期   | 暂停、恢复、结束、放弃和删除会话                 |
| 记忆       | 设置授权、清除记忆、提交聚合训练摘要             |

`SECURITY DEFINER` RPC 必须验证 `auth.uid()`、限制 `search_path`、拒绝未知 JSON 字段，并只返回最小结果。

## 9. RLS 与所有权

- 用户资源表启用 RLS，并以 `auth.uid()` 或所属会话检查访问。
- `question_bank` 允许读取公开题目；收藏仍按用户隔离。
- Agent 审计表主要允许用户读取本人数据，写入通过受控 RPC/服务端流程完成。
- Checkpoint schema 不直接暴露给客户端。
- 新用户表必须同时提供跨用户拒绝测试。

## 10. 数据生命周期

- 用户主动删除会话时，通过受控 RPC 删除或断开关联业务数据，并返回最小删除结果。
- 用户可删除简历、知识文档、QA 会话、Brain 和训练记忆。
- `AGENT_EVENT_RETENTION_DAYS` 定义事件保留目标；实际清理任务必须在部署前单独验证。
- 备份中的数据按基础设施保留策略到期，不承诺即时物理擦除。

## 11. 迁移规则与风险

1. 新 migration 使用唯一 UTC 时间戳，只做增量变更。
2. 迁移同时审查索引、RLS、RPC 所有权、回滚/补救和旧客户端兼容性。
3. 在隔离数据库验证后再申请远端执行授权。
4. migration history 未治理前禁止全量 `db push`、`db reset`、`migration repair` 或修改历史文件。
